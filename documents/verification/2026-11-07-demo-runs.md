## Verified invariants

- Anonymous/backup identities cannot reset the demo.
- Reset/clock identities are idempotent; conflicting reuse is rejected.
- New runs have no previous readings, notes, or alerts; source archives remain inspectable.
- Archived queued data stays in its source run; archived alerts cannot be mutated.
- Late AI completion cannot affect the new active run.
- A 130-second advance makes old readings stale and an unanswered alert overdue using the same clock.
- More than eight advanced demo hours do not expire a wall-time-valid session.
- Repeated presets produce the same counts and concern states; previous runs retain six readings.
- Refresh preserves same-run disconnect state; a new run restores transport controls while preserving pending data.

## Packaging boundary

The startup instrumentation trace was found to include local test database files, even though route traces excluded them. Marked the database path as runtime-only at the source tracing boundary and verified every server trace contained zero `.data/` entries. Build verification now fails if runtime databases or private environment files enter any server trace. This preserves dependency tracing for PGlite's runtime assets while excluding application state.

## Accessibility and review

The initial release browser test failed on six low-contrast labels and a non-focusable horizontally scrolling reading log. Darkened those labels and made reading tables named keyboard-focusable regions. The same test then passed at 320, 768, and 1440 pixels with zero axe WCAG A/AA findings. See `accessibility.json`. Automated scanning is not full accessibility certification.

Keyboard skip-link activation focuses the patient overview. Failed note/action requests retain typed drafts, and successful retries clear only confirmed inputs. Current concern announces changes politely. Advanced clock and active care content do not cause page overflow at the tested widths.

Reviewed correctness, simplicity, module boundaries, security, and bounded queries. Archive lookup now maps only a known missing run to 404; operational errors propagate rather than appearing to be a missing record. No test, assertion, lint rule, or type check was disabled.

The npm advisory [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249) affected `minimatch` in the lint parser chain. Scoped the override to `@typescript-eslint/typescript-estree` → `minimatch` 11.0.1, whose named matcher API and Node engine remain compatible with the installed caller. Lint and complete application checks verify the resulting tree; no broad major-version upgrade was forced.
